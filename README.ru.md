# Social MCP

[English](README.md) · [Русский](README.ru.md)

Подключи свой Threads к MCP-ассистенту: читай публикации и обсуждения, получай
доступную статистику, публикуй контент и модерируй ответы через Threads API.
Сервер работает локально через stdio. Instagram, X и Telegram пока в планах.

**Работает на твоём компьютере. Токены хранятся локально. Облака Social MCP нет.**

## Приватность и движение данных

- Записи аккаунтов и токены хранятся в SQLite на компьютере, где запущен Social
  MCP. У проекта нет облачного сервера, синхронизации БД или встроенной телеметрии.
- По умолчанию сервер также проверяет публичный API релизов GitHub. Данные
  аккаунтов и токены GitHub не передаются. Отключить запрос можно через
  `SOCIAL_MCP_CHECK_UPDATES=false`.
- Сервер обращается напрямую к Threads API. Токены передаются Meta для авторизации
  запросов; Social MCP не включает их в ответы инструментов и не отправляет
  ИИ-модели.
- Профиль, посты, ответы и статистика, полученные инструментами, передаются
  MCP-клиенту. Если ты используешь облачную ИИ-модель, клиент может передавать
  этот контент её провайдеру согласно своим настройкам и правилам. Локальный
  Social MCP не делает обработку в самом ИИ-клиенте локальной.
- Контент, который ты явно поручаешь опубликовать, отправляется Meta для
  публикации. Токены в локальной БД хранятся открытым текстом; подробности в
  разделе [«Хранение и ограничения»](#хранение-и-ограничения).

## Быстрый старт

Установи [uv](https://docs.astral.sh/uv/getting-started/installation/), если его
ещё нет: вместе с ним идёт `uvx`. Агент может выполнить эту настройку за тебя.
Для установки из GitHub также нужен Git. Клонировать проект, создавать окружение
и отдельно устанавливать Python не требуется: `uvx` подготовит изолированное
окружение и при необходимости скачает выбранную версию Python.
Подробнее в [инструкции uv](https://docs.astral.sh/uv/guides/tools/).

Репозиторий: [ituzov/social-mcp](https://github.com/ituzov/social-mcp).

Команды ниже устанавливают релиз `v0.1.1`. Во всех командах используй один тег
релиза. Выпущенные теги не перемещаем: исправления публикуем под новым тегом,
например `v0.1.2`.

Команда запуска сервера:

```bash
uvx --python 3.15.2 --from "git+https://github.com/ituzov/social-mcp.git@v0.1.1" social-mcp
```

Первый запуск скачивает и подготавливает зависимости, поэтому ему нужно дать
завершиться. Последующие запуски используют кеш uv. Если MCP-клиент не находит
`uvx`, укажи абсолютный путь к нему. Сейчас проекту нужен Python 3.15.2 или новее.

Добавь эту команду в MCP-клиент. Клиент сам запускает stdio-сервер при
подключении: держать его в отдельном терминале не нужно. Точный момент запуска
и порядок переподключения зависят от клиента.

**Claude Code** ([документация MCP](https://code.claude.com/docs/en/mcp)):

```bash
claude mcp add --transport stdio social-mcp -- uvx --python 3.15.2 --from "git+https://github.com/ituzov/social-mcp.git@v0.1.1" social-mcp
```

**Codex** ([документация MCP](https://learn.chatgpt.com/docs/extend/mcp)):

```bash
codex mcp add social-mcp -- uvx --python 3.15.2 --from "git+https://github.com/ituzov/social-mcp.git@v0.1.1" social-mcp
```

Для клиентов с JSON-настройками `mcpServers`:

```json
{
  "mcpServers": {
    "social-mcp": {
      "command": "uvx",
      "args": ["--python", "3.15.2", "--from", "git+https://github.com/ituzov/social-mcp.git@v0.1.1", "social-mcp"]
    }
  }
}
```

Если нужно, переподключи MCP в клиенте. Попроси ассистента:

> Подключи мой аккаунт Threads.

Ассистент вызовет `threads_connect` и даст ссылку на локальную страницу. Открой
её на компьютере, где запущен сервер, и вставь токен. Страница поддерживает русский
и английский, учитывает язык браузера и запоминает ручной выбор. Токен не передаётся
через MCP-инструмент и не возвращается модели. После отправки формы попроси
ассистента проверить подключение.

Ещё можно ввести токен скрыто в обычном терминале:

```bash
uvx --python 3.15.2 --from "git+https://github.com/ituzov/social-mcp.git@v0.1.1" social-mcp connect threads
```

Для стандартного запуска `.env` не нужен. Не вставляй токен в чат или настройки MCP.

## Обновление и удаление

Попроси ассистента проверить обновления через `social_mcp_check_update`, затем
поручи обновление, если нужна новая версия. Сам сервер ничего не устанавливает
и настройки клиента автоматически не меняет.

При вызовах инструментов Social MCP проверяет GitHub не чаще раза в шесть часов
на процесс и добавляет одно уведомление о новом релизе к успешному ответу.
Фонового опроса нет: в работающей сессии следующая проверка произойдёт при вызове
инструмента после истечения кеша. Отдельный инструмент по умолчанию проверяет
сразу; `force=false` использует кеш. Сбой сети возвращает `unavailable`, а не
подтверждение актуальности версии, и не мешает другим инструментам.
`SOCIAL_MCP_CHECK_UPDATES=false` в окружении сервера отключает обе проверки.

Для ручного обновления выбери опубликованный релиз, замени закреплённый тег
в настройках клиента и переподключи MCP. Сохрани путь к БД и аккаунты; сначала
сделай согласованную резервную копию SQLite. Версия настраивается отдельно
в каждом MCP-клиенте, даже если они используют общую БД. С `v0.1.0` нужно впервые
обновиться вручную: в ней ещё нет проверки обновлений.
Неизменяемый тег релиза определяет исходники сервера; зависимости `uvx` разрешает
по `pyproject.toml`.
При разработке и в CI используется `uv.lock` через `uv sync --locked`.

Для удаления регистрации MCP:

```bash
claude mcp remove social-mcp
# Или для Codex:
codex mcp remove social-mcp
```

В JSON-настройках удали запись `social-mcp`. Также закрой действующее подключение.
База SQLite и токены при удалении регистрации сохраняются; для удаления аккаунтов
отдельно удали эту БД. `uvx` использует кешируемое окружение, поэтому глобальной
установки `social-mcp` для удаления нет.

## Получить токен Threads

1. Открой [Meta for Developers](https://developers.facebook.com/apps/) и создай
   приложение со сценарием **Access the Threads API**.
2. Добавь свой аккаунт как **Threads Tester** в **App roles → Roles** и прими
   приглашение в [настройках Threads](https://www.threads.com/settings/account).
3. Открой настройки Threads API приложения и сгенерируй пользовательский токен.
4. Вставь его в локальную форму. Повторное подключение того же аккаунта обновляет
   сохранённый токен.

Актуальные шаги в кабинете и требования к правам смотри в
[документации Threads](https://developers.facebook.com/docs/threads/). Здесь
используется готовый токен: настраивать OAuth callback, сертификат и туннель не нужно.

Права нужны **в самом токене**; включить их у приложения недостаточно:

| Возможность | Права, которые используют инструменты |
| --- | --- |
| Профиль и свои публикации | `threads_basic` |
| Статистика публикаций и аккаунта | `threads_manage_insights` |
| Публикация, цитирование, репосты | `threads_content_publish` |
| Чтение ответов и обсуждений | `threads_read_replies` |
| Ответы | `threads_content_publish`, `threads_manage_replies` |
| Модерация | `threads_manage_replies` |
| Удаление своих публикаций | `threads_delete` |

Доступ также зависит от правил Meta и выбранного контента. Наличие права в кабинете
ещё не доказывает, что API разрешит конкретный запрос.

## Инструменты

| Область | Инструменты |
| --- | --- |
| Сервер | `social_mcp_check_update` |
| Подключение | `threads_connect`, `threads_list_accounts`, `threads_get_profile` |
| Публикации | `threads_list_posts` |
| Статистика | `threads_get_post_insights`, `threads_get_account_insights` |
| Обсуждения | `threads_list_replies`, `threads_get_conversation` |
| Модерация | `threads_list_pending_replies`, `threads_moderate_reply` |
| Публикация контента | `threads_publish_text`, `threads_publish_long_text`, `threads_publish_image`, `threads_publish_carousel`, `threads_reply` |
| Действия с постами | `threads_quote_post`, `threads_repost`, `threads_delete_post` |

Попробуй попросить:

- «Покажи мои последние 10 публикаций в Threads».
- «Покажи статистику аккаунта за последнюю неделю».
- «Прочитай обсуждение под этим постом».

Для публикации дай явную команду и точный текст. Инструменты выполняют настоящие
действия; разрешения на их запуск задаются в MCP-клиенте.

## Хранение и ограничения

- Аккаунты и токены хранятся в локальной SQLite, по умолчанию в системной папке
  пользовательских данных `social-mcp`. На POSIX-системах файл имеет права `0600`.
  Токены в БД хранятся открытым текстом; шифрования базы нет.
- Другой путь можно задать через `SOCIAL_MCP_DB_PATH` в переменных окружения
  MCP-клиента. Настройка описана в `.env.example`. Для общей БД между разными
  командами запуска используй абсолютный путь.
- Миграции Alembic из пакета применяются при запуске. Перед обновлением пакета
  сохрани резервную копию БД. Не добавляй её и токены в репозиторий.
- Срок токена проверяется при подключении. Подходящие долгоживущие токены
  обновляются при использовании перед истечением срока. Фонового планировщика нет:
  после простоя дольше срока действия потребуется новый токен.
- Чтение возвращает одну страницу и `next_cursor`. Для продолжения нужны следующие
  страницы; даже у пустой страницы может быть курсор.
- Для изображений и каруселей нужны публичные HTTP(S)-ссылки, доступные Meta.
  Сервер не загружает локальные файлы и приватные вложения.
- Ожидающие одобрения ответы доступны у постов с включённым одобрением ответов.
- Если результат записи неизвестен или запрос завершился таймаутом, сначала проверь
  посты или ответы. Отсутствие ответа от API не означает, что действие не произошло.
- Ленты рекомендаций, поиска публичных постов по словам и публикации видео пока нет.
- Форма доступна только на локальном компьютере и закрывается после подключения
  или отмены. Открывай её там, где работает MCP. Удалённый запуск требует отдельного решения.

## Разработка

Модульный монолит: `accounts` отвечает за хранение аккаунтов, `threads` за работу
с платформой. MCP-инструменты вызывают сервисы, те используют API-клиент и публичный
интерфейс аккаунтов. Границы проверяет import-linter. Правила разработки и
архитектуры описаны в [AGENTS.md](AGENTS.md).

Для разработки склонируй репозиторий и выполни команды в его корне:

```bash
uv sync --locked
uv run ruff check .
uv run ruff format --check .
uv run lint-imports
uv run pytest
uv run pytest --import-mode=importlib
uv build
```

[GitHub Actions](.github/workflows/ci.yml) запускает проверки на push и pull request,
устанавливает wheel в чистое окружение и проверяет миграции, ресурсы переведённых
страниц и настоящее MCP-подключение через stdio. Автопроверки не публикуют посты
и не обращаются к настоящему API Meta.

Для нового языка скопируй `connection/locales/en.json` внутри
`src/social_mcp/threads/`, сохрани ключи и подстановку `{username}`, переведи
значения и задай подпись языка в `language_name`. Переключатель обнаружит его
автоматически. Описания MCP-инструментов и вывод CLI остаются английскими.
