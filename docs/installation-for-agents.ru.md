# Инструкция для агента: установка Social MCP

[English](installation-for-agents.md) · [Русский](installation-for-agents.ru.md)

[Быстрый старт](../README.ru.md#быстрый-старт)

Если пользователь попросил тебя установить Social MCP, выполни шаги ниже.
Этот раздел описывает установку и подключение выпущенного пакета. Правила
разработки самого репозитория находятся в [AGENTS.md](../AGENTS.md).

1. **Определи клиент.** Возьми MCP-клиент и область установки из запроса
   пользователя или существующих настроек. Уточни их, только если определить
   не получается. Прочитай текущую конфигурацию и сохрани посторонние настройки.
2. **Проверь релиз.** Используй тег из раздела [«Быстрый старт»](../README.ru.md#быстрый-старт) или версию,
   указанную пользователем, из `ituzov/social-mcp`. До установки проверь,
   что тег опубликован. Если его нет, сообщи о недоступном релизе; не переключайся
   молча на `main` и не придумывай работающую ссылку на скачивание.
3. **Проверь зависимости установки.** Выполни `uvx --version` и `git --version`.
   Установи только недостающие компоненты по [официальной инструкции uv](https://docs.astral.sh/uv/getting-started/installation/)
   и способом установки Git для выбранной системы, в пределах разрешённой задачи.
   Если MCP-клиент не находит `uvx`, используй абсолютный путь. Клон проекта,
   ручное создание окружения и отдельная установка Python не нужны.
4. **Подготовь пакет.** Возьми закреплённую команду из раздела [«Быстрый старт»](../README.ru.md#быстрый-старт)
   и добавь `--help`. Дождись завершения первой установки зависимостей и проверь
   успешный код выхода. Это проверка запуска команды, а не MCP-подключения.
5. **Зарегистрируй сервер.** Используй команду или JSON-пример для выбранного
   клиента из раздела [«Быстрый старт»](../README.ru.md#быстрый-старт). Укажи запуск **без `--help`** и транспорт
   stdio. Если запись `social-mcp` уже есть, сначала сравни настройки: совпадающую
   оставь без изменений, при необходимости обнови только нужные поля. Не создавай
   дубликат и не перезаписывай другие серверы.
6. **Проверь MCP-подключение.** Переподключи или перезагрузи MCP способом,
   который поддерживает клиент. Убедись, что клиент обнаружил `threads_connect`,
   `threads_list_accounts` и `threads_get_profile`, затем вызови
   `threads_list_accounts`. Пустой список означает успешную первоначальную
   установку. Если текущая сессия не умеет переподключать MCP или вызывать его
   инструменты, дай точный шаг для переподключения и отметь проверку как ожидающую.
   Не объявляй установку проверенной заранее.
7. **Подключи аккаунт, когда пользователь попросит.** Вызови `threads_connect`,
   покажи полученную локальную ссылку и дай пользователю ввести токен в браузере.
   Повторно вызови `threads_connect` для проверки результата. После подключения
   используй полученный ID аккаунта для `threads_get_profile`. Не проси токен
   в чате и не записывай его в настройки MCP. Не публикуй тестовый пост.
8. **Сообщи результат.** Укажи установленный тег, клиент и область установки,
   расположение конфигурации и фактически выполненные проверки. Разделяй установку
   сервера и подключение аккаунта; явно укажи заблокированные или ожидающие шаги.

Настроенная команда должна запускаться без интерактивных вопросов об установке
или секретах. Аккаунт подключается отдельно через инструмент и локальную форму.
