# Инструкция для агента: установка Social MCP

[English](installation-for-agents.md) · [Русский](installation-for-agents.ru.md)

[Быстрый старт](../README.ru.md#быстрый-старт)

Если пользователь попросил тебя установить Social MCP, выполни шаги ниже.
Этот раздел описывает установку и подключение выпущенного пакета. Правила
разработки самого репозитория находятся в [AGENTS.md](../AGENTS.md).

1. **Определи клиент.** Возьми MCP-клиент и область установки из запроса
   пользователя или существующих настроек. Уточни их, только если определить
   не получается. Прочитай текущую конфигурацию и сохрани посторонние настройки.
2. **Проверь релиз.** Используй тег из раздела [«Быстрый старт»](../README.ru.md#быстрый-старт) или версию,
   указанную пользователем, из `ituzov/social-mcp`. До установки проверь,
   что тег опубликован. Если его нет, сообщи о недоступном релизе; не переключайся
   молча на `main` и не придумывай работающую ссылку на скачивание.
3. **Проверь зависимости установки.** Выполни `uvx --version` и `git --version`.
   Установи только недостающие компоненты по [официальной инструкции uv](https://docs.astral.sh/uv/getting-started/installation/)
   и способом установки Git для выбранной системы, в пределах разрешённой задачи.
   Если MCP-клиент не находит `uvx`, используй абсолютный путь. Клон проекта,
   ручное создание окружения и отдельная установка Python не нужны.
4. **Подготовь пакет.** Возьми закреплённую команду из раздела [«Быстрый старт»](../README.ru.md#быстрый-старт)
   и добавь `--help`. Дождись завершения первой установки зависимостей и проверь
   успешный код выхода. Это проверка запуска команды, а не MCP-подключения.
5. **Зарегистрируй сервер.** Используй команду или JSON-пример для выбранного
   клиента из раздела [«Быстрый старт»](../README.ru.md#быстрый-старт). Укажи запуск **без `--help`** и транспорт
   stdio. Если запись `social-mcp` уже есть, сначала сравни настройки: совпадающую
   оставь без изменений, при необходимости обнови только нужные поля. Не создавай
   дубликат и не перезаписывай другие серверы.
6. **Проверь MCP-подключение.** Переподключи или перезагрузи MCP способом,
   который поддерживает клиент. Убедись, что клиент обнаружил `threads_connect`,
   `threads_list_accounts` и `threads_get_profile`, затем вызови
   `threads_list_accounts`. Пустой список означает успешную первоначальную
   установку. Если текущая сессия не умеет переподключать MCP или вызывать его
   инструменты, дай точный шаг для переподключения и отметь проверку как ожидающую.
   Не объявляй установку проверенной заранее.
7. **Проведи настройку аккаунта, когда пользователь попросит.** Следуй разделу
   [«Настройка Threads с нуля»](#настройка-threads-с-нуля). Сначала выясни, что
   у пользователя уже есть. Не останавливайся на ссылке на форму без объяснения,
   где взять токен; доведи подключение до проверки профиля.
8. **Сообщи результат.** Укажи установленный тег, клиент и область установки,
   расположение конфигурации и фактически выполненные проверки. Разделяй установку
   сервера и подключение аккаунта; явно укажи заблокированные или ожидающие шаги.

Настроенная команда должна запускаться без интерактивных вопросов об установке
или секретах. Аккаунт подключается отдельно через инструмент и локальную форму.

## Настройка Threads с нуля

Используй этот маршрут, когда пользователь хочет подключить аккаунт и подходящего
подключения ещё нет. Установка сервера и подключение Threads являются разными
результатами.

Для входа в Meta и настройки приложения предложи обычный браузер пользователя,
где он уже может быть авторизован. Если встроенный просмотр показывает экран
входа или ошибку недоступной страницы, предложи открыть тот же URL в Chrome
или Safari через меню «Открыть в» либо скопировать ссылку. По одной ошибке
предпросмотра не делай вывод, что приложение или аккаунт отсутствует. Вход
пользователь выполняет самостоятельно; не переноси cookies или секреты между
браузерами.

1. **Выясни начальное состояние.** Если это ещё не понятно из разговора, спроси:
   «У тебя уже есть токен Threads, приложение разработчика Meta или начинаем
   с нуля?» Пропускай выполненные шаги. Если токен готов, сразу переходи к форме.
2. **Доступ разработчика.** При необходимости дай ссылку на
   [Meta for Developers](https://developers.facebook.com/) и проведи пользователя
   по текущим экранам регистрации разработчика. Вход, проверку личности и коды
   подтверждения пользователь проходит самостоятельно. Если Meta блокирует
   регистрацию, объясни реальное препятствие и приостанови этот шаг; не обещай
   гарантированную регистрацию и не придумывай способы обхода.
3. **Приложение Threads.** Дай ссылку на [кабинет приложений](https://developers.facebook.com/apps/).
   Помоги создать приложение со сценарием Threads API или использовать уже
   существующее. Веди по одному шагу, уточняй результат и ориентируйся на реальный
   экран, не предполагая названия кнопок и не повторяя уже выполненную настройку.
4. **Тестер и токен.** Помоги добавить нужный аккаунт как Threads Tester и принять
   приглашение в [настройках Threads](https://www.threads.com/settings/account).
   Затем проведи пользователя к генератору пользовательского токена в приложении.
   Выбирай только права для нужных функций: смотри [таблицу прав](../README.ru.md#получить-токен-threads).
   Форме импорта Social MCP не нужны App ID, App Secret, OAuth callback и туннель.
   Если кабинет выглядит иначе, сверься с текущей [документацией Threads](https://developers.facebook.com/docs/threads/)
   и попроси описать экран без секретов.
5. **Ввод токена.** Вызови `threads_connect` и покажи локальную ссылку; на самой
   странице также есть инструкция. Пользователь вставляет токен только в эту
   форму на компьютере, где работает MCP. Не проси токен, пароль, коды
   подтверждения или App Secret в чате и не записывай их в настройки MCP.
6. **Проверка результата.** После отправки формы повторно вызови `threads_connect`.
   Если статус pending, помоги с текущим шагом вместо объявления об успехе.
   При статусе connected вызови `threads_get_profile` с полученным ID и сообщи
   проверенное имя аккаунта. Доступ к профилю не доказывает доступ к публикации
   или статистике. Не публикуй тестовый пост.

## Обновление установленного сервера

Обновляй только по запросу пользователя. Уведомление о версии предлагает
обсудить новый релиз, но не разрешает менять настройки.

1. Проверь закреплённый тег, область установки, окружение и путь к БД выбранного
   клиента. Сверься со [списком релизов](https://github.com/ituzov/social-mcp/releases)
   или вызови `social_mcp_check_update`. По умолчанию `force=true` обходит кеш;
   `unavailable` означает неизвестный результат, `disabled` означает отключение.
2. Проверь выбранный стабильный релиз и подготовь его команду с `--help`.
   Сохрани остальные настройки и клиенты. Не переключайся на `main` и не перемещай
   старые теги.
3. Сделай согласованную резервную копию SQLite через backup API, если БД открыта.
   Храни её приватно; не выводи и не загружай БД или токены. Измени только тег
   релиза выбранного клиента. Не сбрасывай БД и не требуй переподключать аккаунт
   только ради обновления пакета.
4. Переподключи MCP. Проверь обнаружение инструментов и, если доступно,
   установленную версию через `social_mcp_check_update`. Ошибка сети не отменяет
   достоверность локальной версии. Отметь проверки, которые ещё ожидают выполнения.

В `v0.1.0` проверки обновлений нет; для первого обновления нужно изменить тег
напрямую. Версия другого клиента останется прежней, даже если они используют
общую БД по умолчанию.
